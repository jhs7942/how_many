# 몇명이니 (HowMany) — PLAN B 요구사항 ver_3

> 마지막 업데이트: 2026-03-16 (ver_3 — 투표 모드 제거, 단일 플로우 단순화)

## 컨텍스트

ver_2는 투표 모드와 랜덤 돌림판 모드를 병행했으나,
투표 모드는 실시간 동기화·서버·소켓이 필요해 MVP 구현 복잡도가 높았다.
ver_3은 **혼자서 인원수를 선택 → 룰렛으로 활동 결정 → (선택) 장소 랜덤 → 카카오톡 공유**
하는 단일 플로우로 단순화해 핵심 가치에 집중한다.

---

## 1. 서비스 개요

| 항목 | 내용 |
|------|------|
| 서비스명 | 몇명이니 (HowMany) |
| 핵심 컨셉 | 모임 결정 피로를 해결하는 인원 기반 활동·장소 추천 서비스 |
| 목표 | 앱 실행 → 10초 안에 결정 |
| 플랫폼 | 모바일 웹 (카카오톡 인앱브라우저 포함) |

---

## 2. 해결하려는 문제

- 모임에서 "어디 갈지" 단톡방 30분 토론 → 결국 아무거나
- 정보가 없어서가 아니라, 선택지가 너무 많아서 결정 못함
- 지도·리뷰·예약 앱을 오가며 피로 누적

**핵심 가치:** 검색 서비스가 아닌 결정 서비스

---

## 3. 사용자 흐름 (UX Flow)

```
앱 실행
  └─ Splash
      └─ 홈 (인원 선택: 2·3·4·5·6명+)
            └─ 활동 돌림판
                  └─ 활동 결과
                        ├─ 다시 돌리기
                        ├─ 장소도 랜덤으로 정할게 → 장소 돌림판 → 장소 결과
                        └─ 카카오톡 공유
```

## 5. 기능 상세

### 인원 기반 활동 추천
```
2명  → 카페, 산책, 전시
3명  → 카페, 술집, 보드게임
4명  → 노래방, 보드게임, 방탈출, 볼링
5명+ → 고깃집, 술집, 볼링
```

### 활동별 장소 유형 (장소 돌림판)
```
카페      → 분위기 카페, 테이크아웃, 디저트 카페
노래방    → 코인노래방, 일반노래방
보드게임  → 보드게임카페
볼링      → 볼링장
고깃집    → 삼겹살, 소고기, 곱창
방탈출    → 방탈출카페
술집      → 이자카야, 포차, 바
전시      → 미술관, 갤러리
산책      → 공원, 한강, 숲길
```

### 랜덤 돌림판
- 인원 기반으로 추천된 활동 카테고리가 세그먼트로 표시
- 세그먼트 추가/제거 가능 (커스터마이징)
- 스핀 애니메이션 후 결과 강조

### 지도 연결
- 결과 화면에서 "근처에서 보기" 클릭 시 카카오/네이버 지도 새 탭
- 장소 DB 자체 구축 없음 (지도 앱 연결로 대체)

### 공유 기능
- 카카오톡 공유 (Kakao JS SDK)
- 인앱브라우저에서도 동작
- 클립보드 복사 폴백

## 6. MVP 범위

### 포함
- 인원 선택
- 활동 돌림판 (인원 기반 추천)
- 장소 돌림판 (활동 기반 추천, **선택 사항**)
- 지도 연결 (외부 지도 앱)
- 결과 공유 (카카오톡)

### 제외
- 투표 모드 (로비, 방 코드, 닉네임 입력, 제안 입력, 투표 진행 화면 전체)
- 실시간 동기화 / 서버 사이드
- 예약 시스템
- 장소 자체 DB / 리뷰
- 소셜 로그인 / 회원가입
- 마이페이지 / 북마크

## 8. UX 원칙

- 10초 안에 결정할 수 있는 흐름
- 로그인 장벽 없음 — 즉시 사용
- 게임처럼 재밌는 인터랙션 (돌림판)
- 장소는 선택 사항 — 활동만 결정해도 OK
- 지도는 보조 — 직접 DB 없이 외부 지도 앱으로 연결
- 카카오톡 인앱브라우저에서도 공유 작동
