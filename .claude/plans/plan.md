# 몇명이니 (HowMany) — PLAN B 요구사항 ver_5

> 마지막 업데이트: 2026-03-19 (ver_5 — Supabase 도입, 야바위·랜덤의 랜덤·직접설정·위치결정·결과공유 추가)

## 컨텍스트

ver_4는 순수 프론트엔드(sessionStorage)였으나, 실시간 투표·공유가 불가능했다.
ver_5는 Supabase를 도입해 실시간 기능을 구현하고, 야바위·랜덤의 랜덤·직접설정·위치결정·URL 공유를 추가한다.
로그인 없이 참여 가능하며 MVP 중심으로 진행한다.

## 2. 해결하려는 문제

- 모임에서 "어디 갈지" 단톡방 30분 토론 → 결국 아무거나
- 정보가 없어서가 아니라, 선택지가 너무 많아서 결정 못함
- 지도·리뷰·예약 앱을 오가며 피로 누적

**핵심 가치:** 검색 서비스가 아닌 결정 서비스

## 3. 사용자 흐름 (UX Flow)

### 혼자 결정 (ver_5 변경)

```
홈 → [혼자 결정]
  └─ 설정 선택 (기본값 / 직접 설정)
        ├─ 기본값: 인원 선택 → 위치 입력(선택) → 랜덤(돌림판 or 야바위) → 결과
        └─ 직접설정: 항목 직접 입력 → 위치 입력(선택) → 랜덤 → 결과
```

### 같이 결정 — 방 만들기 (ver_5 변경)

```
홈 → [방 만들기]
  └─ 설정 선택 (기본값 / 직접 설정)
        └─ 방 옵션: 인원 + 위치 + 투표/랜덤 모드
              └─ 대기실 (초대코드 + 닉네임 설정 + 참여자 실시간 확인)
                    ├─ 투표 모드: 투표 → 실시간 현황 → 결과
                    └─ 랜덤 모드: 방장 실행 → 전원 동시 관람 → 결과
```

### 같이 결정 — 참여하기 (ver_5 신규)

```
홈 → [참여하기]
  └─ 6자리 코드 입력
        ├─ 실패: 존재하지 않는 코드 → "방을 찾을 수 없습니다"
        ├─ 실패: 만료된 방 → "만료된 방입니다"
        ├─ 실패: 이미 진행 중 → "이미 시작된 방입니다"
        └─ 성공 → 대기실 (닉네임 설정 + 후보 확인 + 참여자 실시간 확인)
              └─ 방장이 시작하면 해당 모드로 자동 전환
```

## 5. 기능 상세

### 야바위 (Shell Game)
- 컵 수 = 후보(컨텐츠) 수 — **빈 컵 없음** (각 컵이 곧 컨텐츠)
- 컨텐츠 최소 2개 이상이어야 야바위 진행 가능
- 컵이 서로 위치를 교환하는 셔플 애니메이션 (2~3초, 8~12회 교환)
- 셔플 후 사용자가 컵 클릭 → 컵이 올라가며 결과 확인
- 그룹에서는 방장 실행 → 전원 동일 화면 실시간 관람, 방장이 컵 선택

### 랜덤의 랜덤
- 돌림판 결과 후 50% 확률로 자동 재회전
- 현재 결과 보여준 뒤 0.5초 후 좌/우 랜덤 방향으로 재회전

### 돌림판 vs 야바위 선택
- 진입 시 앱이 50:50 확률로 자동 선택
- 후보 2~3개: 돌림판/야바위 모두 가능
- 후보 7~8개: 야바위는 모바일 화면에서 컵이 작아질 수 있으므로 돌림판 우선 (야바위 확률 30%로 하향)
- 그룹: 방장 클라이언트가 결정 → DB에 저장 → 참여자 구독

### 실시간 투표 (그룹)
- 투표 현황: **"N/M명 완료"** 표시 + **후보별 득표수 실시간 반영** (예: 볼링 2표→3표)
- **누가 투표했는지는 비공개** — 공정한 투표 유도
- 마감: 전원 완료 자동 + 방장 수동 + 제한 시간(기본 5분)
- 동점 시 방장이 "재투표" 또는 "랜덤으로 결정" 선택
- **참여자 이탈 처리**:
  - 투표 완료 후 이탈 → 투표는 유효, 나간 상태로 그대로 진행
  - 투표 전 이탈 → 최대 투표수(M)를 -1하고 계속 진행

### 실시간 랜덤 공유 (그룹)
- 방장이 실행 → 시드값 DB 저장 → 참여자가 구독
- 동일 시드로 동일 애니메이션 재현 (시드 기반 의사 난수)
- **야바위 그룹**: 방장이 컵을 선택 — 랜덤 모드는 "같이 구경하고, 방장이 대표로 선택"하는 컨셉 (투표와 다른 재미 요소)

### 결과 공유
- 결과를 DB에 저장 → 고유 URL(`/result/[id]`) 생성
- 링크 공유로 결과 확인 가능 (Solo/Group 모두)
- **공유 결과 페이지 표시 내용**: 우승자 카드 + 방식(투표/돌림판/야바위) + 위치(입력한 경우) + 득표 요약(투표인 경우) + "몇명이니에서 결정해보기" CTA

### 다시 하기
- 결과 화면에서 "다시 하기" 버튼 → 같은 설정(인원/후보/위치/모드)으로 재시작
- Solo: 랜덤 화면으로 돌아가 다시 실행
- Group: 방장이 같은 설정으로 새 라운드 시작

### 위치 입력
- 텍스트로 주소 또는 장소명 입력 (선택사항, 건너뛰기 가능)
- 지도 API는 추후 구현 (현재는 placeholder)

### 방장 이탈 처리
- 방장 브라우저 닫힘/이탈 감지 시 "호스트의 연결이 끊겼습니다" 팝업 표시
- 팝업 확인 시 홈 화면으로 이동
- 감지 방식: Supabase Presence Channel (호스트 5초 heartbeat, 30초 미응답 시 이탈 판정)

### 브라우저 새로고침 / 재접속
- client_id(localStorage)로 기존 참여자 인식 → 현재 방 상태에 맞는 화면으로 자동 복구
- 대기실: 다시 대기실로 복귀 (닉네임·이모지 유지)
- 투표 중: 이미 투표했으면 투표 현황, 안 했으면 투표 화면
- 랜덤 진행 중: 결과 화면으로 이동 (애니메이션은 생략)

### 방 만료
- 방 생성 후 1시간 경과 시 만료 — 참여 불가, "만료된 방입니다" 안내
- 진행 중이던 방은 결과까지 완료 가능 (만료는 신규 참여만 차단)

### 직접 설정
- 사용자가 후보 항목을 직접 입력 (텍스트 + 이모지)
- **최소 2개**, 최대 8개 항목
- Solo/Group 모두 사용 가능

### 대기실 — 후보 확인
- 참여자들이 대기실에서 **컨텐츠 후보 목록을 미리 확인** 가능
- 투표 모드: 어떤 후보에 투표할지 미리 파악
- 랜덤 모드: 어떤 후보 중에서 랜덤이 돌아가는지 확인
- **최소 시작 인원**: 방장 포함 2명 이상이어야 시작 버튼 활성화

### 그룹 기본값 모드
- 방장이 인원 선택 → `ACTIVITY_DATA`에서 해당 인원수에 맞는 활동 목록이 자동으로 후보가 됨
- 참여자는 대기실에서 자동 설정된 후보 목록을 확인

### 인원 범위
- 기본값 모드: 인원 선택 2~6명 (기존 ACTIVITY_DATA 유지)
- 직접 설정 모드: 인원 제한 없음 (후보만 입력)
- 그룹 최대 참여자: 20명

## 6. 데이터 모델 (Supabase)

- **rooms**: 방ID, 코드(6자리 UNIQUE), 방장ID(client_id), 모드(vote/random), 프리셋(default/custom), 인원수, 위치, 제한시간(기본 300초), 상태(waiting/voting/random_playing/finished), **created_at**
- **room_candidates**: 후보ID, 방ID, 라벨, 이모지, 순서
- **participants**: 참여자ID, 방ID, client_id, 닉네임, 이모지, 방장여부, last_seen, **joined_at** (UNIQUE: room_id + client_id)
- **votes**: 투표ID, 방ID, 참여자ID, 후보ID (UNIQUE: room_id + participant_id — 1인 1표)
- **results**: 결과ID, 방ID(nullable — Solo 공유용), 우승자라벨, 우승자이모지, 방식(vote/spin/shell), 동점여부, 득표요약(JSONB), 위치, **created_at**
- **random_events**: 이벤트ID, 방ID, 타입(spin/shell), 시드, 결과인덱스, 재회전여부, 재회전방향(left/right), 컵순서(INT[])

### 클라이언트 식별
- 로그인 없이 localStorage에 UUID 저장 (crypto.randomUUID())
- 탭 종료 후 재접속 시에도 동일 참여자로 인식

### Supabase 인프라
- Supabase 프로젝트 신규 생성 필요
- Realtime 활성화 대상: rooms, participants, votes, random_events
- RLS: anon key만 사용하므로 전체 open + 앱 레벨에서 client_id 검증 (추후 anonymous auth 도입 시 강화)

### 중복 참여
- 구현하지 않음 (동일 기기 중복만 DB UNIQUE 제약으로 자연 방지)

### 재입장
- 같은 방 재입장 가능 (client_id 기반으로 기존 참여자로 인식)

## 9. UX 원칙

- 10초 안에 결정할 수 있는 흐름
- 로그인 없음 — 혼자 결정, 같이 결정 모두 즉시 사용 (같이 결정은 닉네임 입력만)
- 투표자 비공개 — 누가 투표했는지 숨기고 후보별 득표수만 실시간 공개
- 게임처럼 재밌는 인터랙션 (돌림판 + 야바위)
- 동점 시 랜덤 결정 버튼 — 핵심 가치(결정 피로 해소) 유지
- 위치는 선택 사항 — 활동만 결정해도 OK
- 카카오톡 인앱브라우저에서도 공유 작동
- 방장 이탈 시 즉시 알림 — 참여자가 무한 대기하지 않도록

## 11. 검증 방법

1. Solo 기본값: 인원 선택 → 위치(건너뛰기) → 랜덤(돌림판 or 야바위) → 결과 → URL 공유
2. Solo 직접설정: 항목 직접 입력 → 위치 → 랜덤 → 결과
3. 랜덤의 랜덤: 돌림판 결과 후 50% 확률 재회전 동작 확인
4. 야바위: 컵 표시 → 셔플 애니메이션 → 컵 선택 → 결과 확인
5. Group 투표: 방 생성 → 코드로 참여 → 대기실 → 투표 → 실시간 득표수 확인(투표자 비공개) → 마감 → 동점 처리 → 결과
6. Group 랜덤: 방 생성 → 참여 → 방장 실행 → 참여자 동일 애니메이션 확인
7. 방장 이탈: 방장 브라우저 닫기 → 참여자에게 "호스트의 연결이 끊겼습니다" 팝업 → 홈 이동
8. 결과 공유: `/result/[id]` URL 접속 → 결과 표시 확인
9. 카카오톡 인앱브라우저에서 전체 플로우 테스트
10. 방 코드 오류: 잘못된 코드 / 만료된 방 / 이미 시작된 방 → 적절한 에러 메시지 확인
11. 방 만료: 1시간 경과 방 접근 시 "만료된 방입니다" 표시
12. 새로고침 복구: 투표 중 새로고침 → 기존 상태(투표 완료/미완료) 유지 확인
13. 참여자 이탈: 투표 전 이탈 → M-1 반영, 투표 후 이탈 → 투표 유지 확인
14. 다시 하기: 결과 화면 → 같은 설정으로 재시작 확인
15. 야바위 컵 수: 후보 2개~8개별 야바위 UI 정상 표시 확인
