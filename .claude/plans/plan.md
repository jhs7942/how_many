## 2. 핵심 가치 및 문제 정의

### 해결하려는 문제
- 모임 장소를 정할 때 **정보가 없어서가 아니라 선택지가 너무 많아 결정하지 못하는 상황**
- 어디서 만날지 의견이 갈림
- 인원 수에 맞는 장소를 바로 찾기 어려움
- 지도, 리뷰, 예약 서비스를 계속 오가야 함
- 결국 결정이 늦어지고 **결정 피로**가 쌓임

### 핵심 가치 3가지
1. **검색보다 결정** - 많은 정보 나열 대신 지금 바로 결정할 수 있는 후보 제시
2. **상황 중심 UX** - 빠르게 보고, 빠르게 고를 수 있는 흐름 우선
3. **카드 중심 구조** - 지도는 보조, 실제 선택은 카드형 추천 리스트에서

### 핵심 사용 플로우
1. 인원 수 선택 → 2. 지역 선택 → 3. 분위기/카테고리 선택 → 4. 장소 추천 → 5. 선택 또는 랜덤 결정

### 화면별 역할 구분 (홈 vs 조건 선택) `(반영)`
- **홈**: 빠른 진입용 간략 선택 (칩 형태로 인원·위치·무드 한 번에)
- **조건 선택**: 상세 멀티스텝 선택 (각 조건을 단계별로 명확하게 선택)

## 3. 타겟 사용자

- 20~30대 모임 사용자
- 친구 약속, 회식, 2차, 동호회, 소모임 이용자
- 장소를 찾는 것보다 **결정을 빨리 끝내고 싶은 사용자**
- 어디 갈지 정하는 데 시간이 오래 걸리는 사람
- 지도앱과 검색앱을 오가며 피로를 느끼는 사람
- 여러 명의 의견을 빠르게 조율해야 하는 사람

## 4. MVP 기능 범위

### 기존 아이디어 (script.md · 노션 기획 기반)
- 인원 선택
- 지역 선택
- 분위기/카테고리 선택
- 장소 추천 리스트
- 랜덤 결정 기능
- 네이버 지도 URL 새 탭 열기 (map.naver.com, 실제 예약 API 미사용)

### 반영 기능 (Claude 제안 + input.md 결정 사항)
- 장소 저장/북마크 (재방문 유인) `(반영)`
- 결과 공유 기능 (카카오톡 공유 SDK - 인앱브라우저 포함, 모임 서비스 특성상 핵심) `(반영)`
- 최근 검색 조건 저장 + 홈 원탭 재사용 `(반영)`
- 추천 결과 정렬 (거리순 / 인기순) `(반영)`
- 가격대 필터 - 사용자가 직접 범위 입력 (1인당 예산 기준) `(반영)`
- 하단 네비게이션 바 (홈 / 마이페이지 탭) `(반영)`
- 불호 필터: 원하지 않는 카테고리 제외 선택 (e.g. 방탈출 제외, 노래방 제외) `(반영)`
  - ※ 카테고리 선택(포함)과 불호 필터(제외)는 별도 UX로 구분 — 카테고리는 대분류 포함 선택, 불호 필터는 세부 업종 제외 선택
- 현재 영업 중 필터: 현재 시간 기준 영업 중인 장소만 표시 토글 `(반영)`
  - ※ Mock 데이터에 `openingHours: { open: string; close: string }` 필드 필수

### 제외 기능 (MVP 이후)
- 공동 투표
- 정산 기능
- 모임 기록
- 그룹 기능
- 실시간 방 생성
- 미니게임 요소

### 인증 및 게스트 정책 `(반영)`
- **비회원(게스트)**: 홈·조건 선택·추천 결과·장소 상세 허용
- **로그인 필요**: 북마크 저장, 최근 검색 조건 저장, 마이페이지 (방문 이력 + 찜 목록)
- 온보딩 완료 후 로그인은 선택 → skip 버튼으로 홈 바로 진입 가능

### MVP 성공 기준
> **사용자가 모임 장소를 더 빠르게 결정할 수 있는가?**

## 5. 화면 구성

### 전체 화면 목록 (12개)

#### 1. 스플래시 화면
- 앱 로고
- 짧은 브랜드 태그라인
- 따뜻하고 깔끔한 첫인상

#### 2. 온보딩 화면 1
- 빠르게 장소를 결정할 수 있다는 내용 설명
- 간단한 일러스트 또는 비주얼
- 짧고 감성적인 카피

#### 3. 온보딩 화면 2
- 인원수 기반 추천 설명
- 빠른 결정 및 쉬운 비교 강조

#### 4. 온보딩 화면 3
- 랜덤 추천 기능을 재미있는 선택지로 소개
- 부드럽고 플레이풀하지만 미니멀 유지
- skip 버튼 (재방문 사용자 빠른 진입) `(반영)`

#### 5. 로그인 / 회원가입 화면
- 심플하고 우아한 레이아웃
- 이메일 로그인 + 소셜 로그인
- 최소한의 입력 필드, 명확한 CTA
- 건너뛰기 버튼 (게스트 진입) `(반영)`

#### 6. 홈 화면
- 서비스 소개
- 인원수 선택 (칩)
- 위치 선택 (칩)
- 무드/카테고리 선택 (칩)
- 메인 CTA 버튼
- 최근 인기 장소 섹션
- 최근 검색 조건 칩 (로그인 사용자, 원탭 재사용) `(반영)`

#### 7. 조건 선택 화면
- 인원수 선택: 1-2명 / 3-5명 / 6명 이상
- 지역/위치 선택: 강남, 홍대, 이태원, 신촌, 건대, 성수, 종로, 여의도 등 핵심 상권
- 무드 선택: 조용한, 활기찬, 뷰 좋은, 힙한, 아늑한, 고급스러운
- 카테고리 선택(포함): 식당, 카페, 술집, 복합공간 (대분류, 보고 싶은 것 선택)
- 가격대 입력: 1인당 예산 범위 직접 입력 (e.g. 1만원 ~ 3만원) `(반영)`
- 불호 필터(제외): 세부 업종 제외 다중 선택, 선택 안 해도 됨 (e.g. "방탈출 제외", "노래방 제외") `(반영)`
  - ※ 카테고리와 중복되지 않도록 세부 업종(방탈출, 노래방, PC방 등) 기준으로 구성
- 현재 영업 중 필터: 토글 버튼 ON/OFF `(반영)`
- 선택 요약 섹션
- 계속하기 버튼

#### 8. 추천 결과 화면
- 상단: 선택 조건 요약
- 중단: 장소 카드 리스트 (썸네일·장소명·카테고리·추천이유·인원 적합성·거리)
  - 거리: 선택한 지역 중심점 기준 표시 (위치 권한 없이도 동작) `(반영)`
  - 정렬: 거리순 / 인기순 탭 `(반영)`
- 보조 기능: 랜덤 선택 플로팅 버튼
- 공유 버튼 (카카오톡 공유 SDK) `(반영)`
- 로딩 시 스켈레톤 UI 표시 `(반영)`
- 에러 상태 UI (네트워크 오류 등) `(반영)`

#### 9. 랜덤 결정 화면
- 시각적으로 매력적인 카드 공개 인터랙션
- 랜덤으로 선택된 장소 1개
- "다시 뽑기" 및 "이 장소로 결정" 버튼
- 카카오 지도로 해당 장소 위치 함께 표시 (카드 하단) `(반영)`

#### 10. 장소 상세 화면
- 큰 히어로 이미지
- 장소명
- 카테고리 / 무드 / 인원 적합도
- 짧은 추천 요약
- 위치 정보
- 영업시간 표시 `(반영)`
- 가격대 표시 `(반영)`
- 북마크 버튼 (히어로 이미지 위 오버레이) `(반영)`
- 예약 CTA: "네이버 지도에서 보기" 버튼 → map.naver.com 새 탭 열기 `(반영)`

#### 11. 빈 결과 화면
- 우아한 빈 상태 디자인
- 재시도 CTA
- 유사 추천 장소 섹션 (조건 중 무드·카테고리 기준으로 유사 장소 표시)

#### 12. 마이페이지 `(반영)`
- 방문 이력: 사용자가 "방문 완료" 표시한 장소 목록 (네이버 지도 URL 방식으로 예약 완료 여부를 알 수 없으므로, 사용자가 직접 방문 표시)
- 찜한 장소 목록 (북마크 리스트)
- 각 섹션 비어 있을 때 빈 상태 UI + 추천 시작 CTA
- 로그인 필요 (비회원 접근 시 로그인 유도)

## 8. UX 원칙

- 정보량보다 **결정 속도** 우선
- 지도는 메인이 아닌 보조 역할
- 랜덤 기능은 재미 요소이지만 주 흐름 방해하지 않도록 배치
- 한 화면 안에서 "보고 → 비교 → 결정" 가능
- CTA는 "네이버 지도에서 보기", "길찾기", "다시 추천받기"처럼 명확하게
