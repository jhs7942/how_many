## 개선 제안 (내부 분석)

### Nice-to-have (가까운 미래)

- **`.env.local`에 `CAPACITOR_SERVER_URL` 관리**
  - 현재 plan은 shell inline env 주입만 상정. `.env.local`에 저장 시 Next.js가 자동 주입하므로 빌드 스크립트 단순화 가능.
  - 단점: `.env.local`은 gitignore라 팀원 간 공유 불가 → 각자 설정 필요.
  - 결정: 이번 작업에는 shell env + `.env.example` 문서화로 진행, 추후 팀원 온보딩 빈도 증가 시 재검토.

- **dev 빌드 커맨드에 pre-check 추가**
  - `if [ -z "$CAPACITOR_SERVER_URL" ]; then echo "SERVER_URL 미설정" && exit 1; fi` 형태로 환경변수 누락 시 빌드 실패시키기.
  - fallback이 prod URL이라 누락이 조용히 넘어갈 수 있음 → 명시적 에러가 더 안전.
  - 이번 작업에는 fallback 방식 유지, 사고 발생 시 전환.

- **Vercel preview URL 고정**
  - 기본 preview URL(`how-many-git-develop-*.vercel.app`)은 팀명·프로젝트명 변경 시 깨짐.
  - Vercel 프로젝트 설정 → Domains에서 develop 브랜치에 고정 도메인(예: `how-many-dev.vercel.app`) 할당 가능.
  - 결정: Task 001 완료 후 URL 패턴이 안정적인지 확인, 불안정하면 이 방식 채택.

### Future (먼 미래)

- **Android build flavor 분리 (`com.howmany.app.dev`)**
  - 같은 기기에 dev·prod 앱 병렬 설치 가능 → 기획자 실사용 환경과 QA 환경 완전 격리.
  - Gradle `productFlavors` + Capacitor config 주입 스크립트 필요.
  - 트리거: 기획자가 "내부 테스트 설치 시 실사용 앱이 덮어써지는 게 불편"이라고 피드백할 때.

- **Supabase dev 프로젝트 분리**
  - dev에서 만든 방·투표·결과가 prod DB에 쌓이는 문제.
  - 현재는 데이터 양이 적어 소각 용이, 스키마 변경 빈도도 낮음.
  - 트리거: 스키마 마이그레이션 빈도 증가 또는 dev 데이터 오염 사고 발생 시.

- **Firebase App Distribution 연동**
  - Play 내부 테스트는 심사·롤아웃 지연이 있음. App Distribution은 "링크 보내면 설치" 방식으로 가볍다.
  - 현재는 테스터가 2명(기획자 1명)이라 Play만으로 충분.
  - 트리거: 외부 테스터 5명 이상 추가 시.

- **GitHub Actions CI/CD 자동화**
  - develop push 시 자동으로 dev AAB 빌드 → Firebase App Distribution 배포.
  - main push 시 자동으로 prod AAB 빌드 → Play 프로덕션 트랙 업로드.
  - 현재는 수동 빌드, 릴리즈 빈도가 낮아 자동화 ROI 낮음.
  - 트리거: 주 1회 이상 릴리즈 시작 시.

- **dev AAB에 디버그 마커**
  - 앱 내 헤더/풋터에 "DEV" 배너, 또는 앱 이름에 "(DEV)" suffix 표시.
  - 기획자가 실수로 dev 앱에서 실사용자처럼 행동하지 않도록.
  - 트리거: flavor 분리와 함께 진행.

## 기술 부채

- **versionCode 수동 관리**
  - 현재 `android/app/build.gradle`의 versionCode를 매 릴리즈마다 손으로 증가.
  - dev/prod 트랙이 공존하면서 단조 증가 규칙을 놓칠 위험.
  - 개선안: gradle에서 `versionCode = System.getenv("VERSION_CODE") ?: 1` 형태로 외부 주입, 빌드 스크립트가 `list_artifacts` MCP로 최대치 조회 후 +1.
  - 우선순위: Low (현재 릴리즈 빈도가 낮아 수동 관리로 충분).

- **Capacitor config가 빌드 타임 결정**
  - `server.url`이 빌드 시점에 고정 → 런타임에 URL 전환 불가.
  - 네이티브 앱처럼 앱 내 디버그 메뉴로 환경 전환하려면 추가 코드 필요.
  - 이번 작업 범위 외.
