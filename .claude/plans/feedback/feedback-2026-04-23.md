## 개선 제안 (내부 분석)

### Nice-to-have

#### 1. ContentShuffle n≥8 overflow 해결
- **배경**: HM-28 수정(커밋 `00a2efe`)에서 `ContentShuffle`의 CUP_W 하한을 36px로 설정. 이로 인해 n이 클 때(예: vp=360, n=8 → container 372px) 가용 폭을 초과하는 overflow가 여전히 남음
- **영향**: 7명 이상 그룹에서 셔플이 선택되면 컵 일부가 화면 밖으로 잘림. `pickGameType`이 `count ≥ 7`에서 rope만 제외하고 ContentShuffle은 허용하므로 실제 발생 가능
- **해결 옵션** (트레이드오프 있음):
  - A. `pickGameType`에서 ContentShuffle도 `count ≥ 7` 제외 — 가장 단순, 게임 다양성 손실
  - B. n≥7일 때 컵을 2줄 grid로 wrap 배치 — UI 변경 큼, 애니메이션 로직 재설계 필요
  - C. 하한을 28-32px로 더 낮춤 — 이모지 식별성 저하, 탭 히트영역 접근성 기준 아래
- **우선순위**: Low (발생 빈도가 낮은 edge case)
- **연관 파일**: `components/ContentShuffle.tsx`, `lib/utils.ts:pickGameType`

#### 2. SpinWheel 텍스트 회전 가독성 (HM-29 부수 관찰)
- **배경**: HM-29 첨부 스크린샷에서 12개 섹터 돌림판의 텍스트가 각도에 따라 거꾸로 표시되어 읽기 어려움 (예: "중식", "일식", "양식"이 뒤집힘)
- **현재 동작**: SpinWheel 내부 Canvas drawText가 섹터 중심선 각도대로 회전 → 하단부는 180° 회전되어 뒤집힘
- **해결 방향**:
  - 섹터가 아래쪽 반원에 위치할 때 텍스트를 180° 추가 회전하여 항상 "머리 위"가 바깥쪽을 향하게
  - 또는 모든 텍스트를 horizontal 고정 (섹터 각도와 무관, 읽기 쉬움)
- **우선순위**: Medium (HM-29 재구조화와 함께 처리 시 효율적)
- **연관 파일**: `components/SpinWheel.tsx` (drawText 로직)

### 6. ESLint v9 config 부재
- **배경**: `npm run lint` 실행 시 "ESLint couldn't find an eslint.config.(js|mjs|cjs) file" 에러. 프로젝트가 ESLint v9.39를 사용하나 config가 구버전 포맷(.eslintrc.*)이거나 누락

- **해결**: `eslint.config.mjs` 마이그레이션 또는 v8로 다운그레이드
- **우선순위**: Medium (품질 인프라)
