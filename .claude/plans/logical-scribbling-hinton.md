## ✅ 확정된 방향

"같이 결정" 모드는 두 가지 결정 방식을 사용자가 선택:
- **투표** — 후보를 제시하고 참여자들이 투표. 비동기 가능
- **돌림판** — 후보를 세팅하고 함께 돌림판 스핀. 그룹 참여형

---

## 1단계: 현재 계획의 문제 진단

### 진단 #1 — 정체성 분열 (Identity Split)
**증상:** "혼자 결정"은 돌림판 앱, "같이 결정"은 투표 앱. 하나의 서비스에 두 개의 다른 앱이 공존.
**리스크:** 사용자가 앱의 핵심 가치를 한 문장으로 설명하지 못함 → 바이럴 약화

### 진단 #2 — 핵심 가치와의 충돌
**증상:** "앱 실행 → 10초 안에 결정"이 목표인데, "같이 결정"의 마감 시간은 최소 1시간.
**리스크:** UX 원칙 자체가 모드에 따라 달라짐 → 브랜드 메시지 혼선

### 진단 #3 — MVP 복잡도 급증
**증상:** ver_3(화면 6개) → ver_4(화면 13개). 개발량 2배 이상 증가.
**리스크:** 카카오 메시지 API 심사, 서버 인프라(DB, Cron), 인증 플로우까지 추가 → 출시 지연

### 진단 #4 — 카카오 메시지 API의 현실적 제약
**증상:** 카카오 메시지 API는 '나에게 보내기'를 제외한 친구 발송은 **카카오 비즈 앱 심사 필수**.
**리스크:** 심사 기간 수주 소요 → MVP 일정 차질. 대안 없으면 알람 기능 통째로 불가

## 2단계: 대안 3가지

---

### 대안 A: 로그인 없는 익명 투표 ("링크 투표")
> 핵심: 카카오 로그인·알람 제거 → 링크 하나로 투표 참여

**변경 내용:**
- 카카오 로그인 → 제거. 닉네임만 직접 입력 (e.g. "홍길동")
- 마감 알람 → 제거. 방장이 결과 링크를 직접 카카오톡으로 공유
- 참여 인증 → 브라우저 세션 기반 중복 방지 (로컬스토리지)
- 마감 시간 → 그대로 유지 (방장 설정)

**UX 흐름:**
```
홈 → 같이 결정
  └─ 닉네임 입력 (방장)
        └─ 투표 방 생성 (후보 + 마감시간)
              └─ 초대 링크 복사 / 카카오톡 공유
                    └─ 참여자: 링크 클릭 → 닉네임 입력 → 투표
                          └─ 마감 후 방장이 결과 링크 공유
```

**장점:**
- 개발 복잡도 최저 (서버 필요하지만 인증 없음)
- 진입 장벽 없음 → 카카오 없는 사용자도 참여 가능
- 빠른 출시 가능

**단점:**
- 중복 투표 완벽 방지 어려움 (세션 우회 가능)
- 알람 없음 → 사용자가 마감 직접 확인 필요

---

### 대안 B: 빠른 실시간 투표 ("스피드 투표")
> 핵심: 마감 시간을 1~10분으로 단축 → "10초 결정" 가치와 정합성 회복

**변경 내용:**
- 마감 시간 범위: 1시간~7일 → **1분~10분** (선택지: 1분/3분/5분/10분)
- 투표 대기 화면: 실시간 폴링(3초 간격)으로 참여 인원 업데이트
- 알람: 마감 시 화면 자동 전환 (폴링) → 카카오 알람 불필요
- 카카오 로그인: 유지 또는 닉네임 방식으로 대체

**UX 흐름:**
```
홈 → 같이 결정
  └─ 방장: 후보 입력 + 마감 시간 선택 (1/3/5/10분)
        └─ 초대 링크 공유 (카카오톡)
              └─ 참여자: 링크 → 투표 (제한 시간 내)
                    └─ 마감 → 전원 결과 화면 자동 전환
```

**장점:**
- "10초 결정" → "10분 이내 결정"으로 일관성 유지
- Cron job·알람 API 불필요 → 개발 단순화
- 실시간 참여 현황이 긴박감 부여 → 재미 요소

**단점:**
- 모든 참여자가 동시에 접속해야 → 시간 맞추기 번거로움
- 마감 10분 내 카카오톡 공유·참여·투표 완료 필요

---

### 대안 C: "같이 결정" = 돌림판 통합 ("그룹 돌림판")
> 핵심: 투표 방식 대신 돌림판을 그룹에 적용 → 앱 정체성 유지

**변경 내용:**
- 투표 UI 제거. 대신 방장이 후보를 돌림판에 세팅
- 그룹원이 각자 "스핀 승인" 버튼 클릭 → 다수가 승인하면 방장이 돌림판 돌림
- 결과는 방장 화면에서 실시간 공유 (화면 공유 유도)
- 카카오 로그인 불필요

**UX 흐름:**
```
홈 → 같이 결정
  └─ 후보 입력 (2~5개)
        └─ 링크 공유 → 그룹원 입장 (닉네임만)
              └─ 전원 "돌릴게요!" 버튼 클릭
                    └─ 방장 화면에서 돌림판 스핀
                          └─ 결과 공유
```

**장점:**
- 기존 돌림판 인터랙션 완전 유지 → 브랜드 일관성 최고
- 그룹원이 참여하는 재미 (투표보다 더 게임적)
- 개발 단순 (투표 DB 불필요, 실시간 인원 카운트만 필요)

**단점:**
- "모두가 동시에 접속" 필요 → 비동기 사용 불가
- 진지한 의사결정보다는 가벼운 놀이에 가까움

## 4단계: 확정된 구조 — 투표 + 돌림판 병행

### 전체 UX 분기 구조

```
앱 실행
  └─ Splash
      └─ 홈 (모드 선택)
            ├─ [혼자 결정]
            │     └─ 인원 선택 → 활동 돌림판 → 결과 → 장소 돌림판(선택) → 공유
            │
            └─ [같이 결정]
                  └─ 결정 방식 선택
                        ├─ [투표]
                        │     └─ 카카오 로그인 → 방 생성(후보+마감) → 초대 링크
                        │           └─ 참여자 투표 → 대기 → 마감 → 알람 → 결과
                        │
                        └─ [돌림판]
                              └─ 후보 입력 → 링크 공유 → 참여자 입장(닉네임)
                                    └─ 전원 준비 → 방장 스핀 → 결과 공유
```

### 주요 설계 원칙

- **투표**: 비동기 (참여자 시간 달라도 OK), 마감 후 카카오 알람, 마감 전 득표 비공개
- **돌림판**: 동기 (전원 동시 접속), 닉네임만으로 참여 (로그인 불필요), 방장이 스핀
- **공통**: 동점/무승부 시 랜덤 버튼, 카카오톡 결과 공유

### MVP 단계 전략

```
v1.0 (출시): 혼자 결정 + 같이 결정(그룹 돌림판)  ← 카카오 API 심사 없이 빠른 출시
v1.5 (검증 후): 같이 결정(투표) + 카카오 로그인 + 마감 알람
v2.0 (성장기): 마이페이지 + 히스토리 + 투표 수정
```
