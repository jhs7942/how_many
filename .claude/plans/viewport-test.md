# 뷰포트 시각 검증: 몇명이니

## 검증 환경
- BASE_URL: http://localhost:3000
- 검증 페이지: /, /solo/people, /solo/spin, /group/create, /group/invite
- 촬영 뷰포트: 6개 (320 ~ 1200px)
- 검증 일시: 2026-03-31

## 참고 사항
- /group/invite 페이지는 sessionStorage에 roomCode가 없으면 /group/create로 리다이렉트됨 (정상 동작)
- /solo/spin 페이지는 sessionStorage에 people 값이 없는 상태에서 촬영 (기본 활동 목록 표시)

### /group/create (방 만들기)

| 뷰포트 | 너비 | 결과 | 주요 이슈 |
|--------|------|------|-----------|
| mobile-portrait | 320px | PASS | 태그 버튼들 자연스러운 줄바꿈, 좌측 짤림 없음 |
| mobile-landscape | 480px | PASS | 없음 |
| tablet-sm | 600px | PASS | 없음 |
| tablet | 768px | PASS | 없음 |
| laptop | 1024px | MEDIUM | 430px 컨테이너 내 폰트가 상대적으로 작아 보임 |
| desktop | 1200px | MEDIUM | 430px 컨테이너 내 폰트가 상대적으로 작아 보임 |

**분석**: 가장 복잡한 레이아웃을 가진 페이지. 주요 구성요소:
- **후보 설정 방식 탭**: "요즘 인기 기반" / "직접 입력" 토글이 320px에서도 정상 배치
- **추천 활동 태그**: 카페, 산책, 전시, 영화, 피크닉, 드라이브 등 태그 버튼들이 flex-wrap으로 자연스럽게 줄바꿈됨. 선택된 태그(보드게임, 방탈출, 노래방 등)가 오렌지 배경으로 잘 구분됨
- **후보 목록**: 보드게임, 노래방, 방탈출, 볼링이 리스트 형태로 정상 표시, x 삭제 버튼 정상
- **입력 필드**: "후보 추가..." 입력칸과 "추가" 버튼 정상 배치
- **위치 입력**: "예: 강남역, 홍대..." 플레이스홀더 정상
- **방 만들기 CTA**: 하단 고정 오렌지 버튼 정상 표시

320px에서도 모든 요소가 좌측 짤림 없이 정상 렌더링됨. 태그 버튼의 텍스트도 잘리지 않음.

## 발견된 이슈

### [MEDIUM] 넓은 뷰포트에서 앱 컨테이너 비율 대비 폰트 크기 부조화
- 페이지: /group/create (전체 페이지 해당)
- 뷰포트: laptop (1024px), desktop (1200px)
- 스크린샷: .claude/viewport-test/screenshots/group_create/laptop.png, desktop.png
- 현재: 430px 최대 너비 컨테이너 내부의 UI 요소(태그 버튼, 입력 필드, 텍스트)가 넓은 화면 대비 상대적으로 작아 보임. 특히 laptop/desktop 스크린샷에서 추천 활동 태그들과 후보 목록 텍스트가 주변 여백에 비해 작게 느껴짐.
- 제안: 모바일 전용 앱이므로 의도된 디자인일 수 있음. 데스크톱 사용자 비율이 높다면 max-width 확장 또는 폰트 스케일링 고려. 현재 상태로도 기능 사용에 문제 없음.

### [LOW] Naver 지도 아이콘(N)이 앱 컨테이너 밖에 고정 위치
- 페이지: 전체 페이지 (/, /solo/people, /solo/spin, /group/create)
- 뷰포트: 전체 (특히 600px 이상에서 두드러짐)
- 스크린샷: 모든 스크린샷 좌측 하단에서 확인 가능
- 현재: "N" 마크가 있는 원형 아이콘이 화면 좌측 하단에 `position: fixed`로 표시됨. 430px 앱 컨테이너와 무관하게 브라우저 좌측 하단에 고정되어 있어, 넓은 화면에서는 앱 영역 밖에 위치함. 320px 모바일에서는 앱 영역과 겹쳐 보이나 콘텐츠를 가리지는 않음.
- 제안: 해당 아이콘의 position을 앱 컨테이너(430px) 내부로 제한하거나, 필요 없다면 제거 고려. 최소한 앱 컨테이너의 left 경계를 기준으로 배치하면 일관성 향상.

### 핵심 결론

1. **좌측 콘텐츠 짤림 현상**: 완전히 해결됨. 320px 소형 모바일에서도 모든 페이지(인원 선택 카드, 돌림판, 방 만들기 태그/폼)의 콘텐츠가 좌측 짤림 없이 정상 표시됨. 최근 커밋(0e9a416 "좌측 콘텐츠 짤림 근본 해결")의 수정이 효과적으로 반영됨.
2. **버튼 레이아웃**: 모든 뷰포트에서 정상. 인원 선택 카드(3열 그리드), SPIN! 원형 버튼, "방 만들기" CTA 버튼, 추천 활동 태그 버튼 등 모든 인터랙티브 요소가 적절한 크기와 위치로 렌더링됨. 터치 타겟 크기도 충분.
3. **돌림판(SpinWheel) 렌더링**: Canvas 기반 돌림판이 320~1200px 전체 범위에서 정상 동작. 320px에서도 뷰포트에 맞게 비례 축소되며 세그먼트 텍스트/이모지 가독성 유지. 중앙 포인터, 외곽 테두리, 세그먼트 구분선 모두 깔끔.
4. **텍스트 오버플로우**: 발견되지 않음. 모든 텍스트(헤더, 서브텍스트, 태그 라벨, 입력 플레이스홀더)가 컨테이너 내에서 정상 렌더링. 줄바꿈도 자연스러움.
5. **전체 레이아웃 정합성**: 430px max-width 모바일 앱 레이아웃이 모든 뷰포트에서 일관되게 동작. 앱 컨테이너 중앙 정렬, 배경색 처리, 콘텐츠 패딩 모두 정상.
