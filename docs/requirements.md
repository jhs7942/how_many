# 요구사항정의서

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | 몇명이니 |
| 목적 | 모임에서 활동/맛집 결정을 랜덤 게임으로 빠르게 해결 |
| 타겟 사용자 | 친구/가족/동료 모임에서 결정 피로를 겪는 20~30대 |
| 슬로건 | "모임 결정, 10초면 충분해" |
| 플랫폼 | 모바일 웹 (주), Android 앱 (부) |

## 2. 기능 요구사항

### FR-01. 홈 화면

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| FR-01-01 | 첫 방문 시 스플래시 화면을 2초간 표시한다 | 필수 |

## 4. 사용자 시나리오

### 시나리오 1: 혼자서 활동 결정

> 대학생 A는 4명 모임에서 뭘 할지 결정해야 한다. "혼자 결정"을 누르고, "인원기반 추천"을 선택한 뒤 인원수 4를 입력한다. 강남역 근처라서 위치에 "강남"을 입력한다. 돌림판이 돌아가고 "볼링"이 나온다. 카카오맵 버튼을 눌러 "강남 볼링"을 검색하고, 결과 링크를 단톡방에 공유한다.

### 시나리오 2: 맛집 결정

> 직장인 B는 점심 메뉴를 못 정하고 있다. "맛집 결정"을 누르고 "추천 메뉴로 뽑기"를 선택한다. 회사 근처 "여의도"를 입력하고 슬롯머신이 돌아가 "일식"이 나온다. "세부 메뉴 뽑기"를 눌러 2차 게임을 하니 "라멘"이 나온다. 네이버지도에서 "여의도 라멘"을 검색한다.

### 시나리오 3: 친구들과 투표

> C가 5명 모임의 주말 활동을 정한다. "같이 결정"으로 방을 만들고 후보(영화, 카페, 볼링, 노래방)를 등록한다. 초대 코드를 단톡방에 공유한다. 친구 4명이 코드를 입력하고 닉네임을 설정한 뒤 각자 투표한다. 투표가 완료되면 랜덤 게임으로 최종 결정한다. 모든 참여자의 화면에 동일한 결과가 표시된다.

### 시나리오 4: 직접 입력

> D는 자기만의 후보 목록이 있다. "혼자 결정" -> "직접 입력"으로 들어가 "스터디카페", "도서관", "집"을 입력한다. 프리셋에서 "PC방"도 추가한다. 셔플 게임이 실행되고 컵을 클릭해 결과를 확인한다.

### 시나리오 5: 결과 공유 링크 열기

> E는 단톡방에서 친구가 보낸 결과 링크를 클릭한다. `/result/[id]` 페이지에서 "오늘의 활동: 볼링"과 위치 정보를 확인한다. 카카오톡으로 재공유한다.
